# Working in this repository

Orientation for coding agents (and humans) seeing this repo for the
first time. Everything here was verified against the tree as written;
if reality and this file disagree, fix this file in the same change.

## What this is

A Python model layer (`gbforge/`) that compiles declarative
puzzle-game specs into C configuration tables, a shared hand-written
Game Boy Color runtime (`runtime/`) that consumes them, one complete
worked example (`examples/cascadia/`), a headless emulator harness
(`harness/`), and the macOS art tool that owns the example's asset
source files (`tools/sprite-editor/`).

The README's numbers are measured from this tree and end up in front
of readers who may verify them — if your change moves a number,
re-measure and update.

## Environment setup

1. **Python 3.9+** — codegen, asset generation, and the harness client
   are stdlib only. `python3 -m gbforge build examples/cascadia -o
   examples/cascadia/generated` should work from the repo root
   immediately.
2. **GBDK-2020 4.5.0+** — the C toolchain (SDCC + lcc + ROM tools).
   Download a release from
   https://github.com/gbdk-2020/gbdk-2020/releases, unpack anywhere,
   and point `GBDK_HOME` at its root (the directory containing
   `bin/lcc`). The path must end with a slash:

   ```bash
   export GBDK_HOME=/opt/gbdk/     # trailing slash matters
   ```
3. **A host C compiler + git**, for the harness. `make -C harness
   gbctl` fetches SameBoy at a pinned tag and builds it once (~1 min).
4. **Swift** (Xcode toolchain), only if you touch the art tool.

Full check from a fresh clone:

```bash
GBDK_HOME=/opt/gbdk/ ./scripts/verify.sh
```

That runs, in the order that fails fastest: codegen reproducibility,
the engine transcript, both ROM builds, the emulator scenarios, and
the asset boundary. **Run it before declaring anything done.**

## Working in parallel

Several agents at once is the expected case, and the repo is arranged
for it. Read this before starting.

- **Use a worktree.** `git worktree add ../wt-<topic> -b <topic>`.
  `scripts/verify.sh` links the heavy gitignored dependencies
  (`harness/sameboy`) from the main checkout, so a new worktree is
  usable in seconds rather than after a rebuild.
- **Know which surface you are on.** Spec/model, codegen, runtime,
  res, and scenarios change for different reasons and rarely need to
  change together. If your task seems to need all five at once, say so
  before writing code — that is usually a sign the task is really two
  tasks.
- **ROM banks are the shared resource.** Adding code to a full bank
  makes the linker place it at an address that is not code, silently.
  `scripts/check_banks.py` runs on every link and turns that into a
  build error. Do not disable it, and expect to have to think about
  bank placement if two branches both grow the ROM.
- **The transcript hash is the merge gate for engine changes.** If you
  change `runtime/engine.c`, `gbforge/engine/sim.py` changes with it
  in the same commit, and `make -C tests` must still agree over 10,000
  boards.
- **Regenerate, don't hand-edit, and commit the outputs together with
  the source change** — otherwise the next agent's `verify.sh` fails
  on a diff they didn't cause.

## Test environment

Three layers, cheapest first. Use the cheapest one that can see your
change.

**`make -C tests`** — host-native. `runtime/engine.c` is a pure
function (board in, event list out), so it compiles with the host
compiler and folds 10,000 boards into a transcript hash that must
equal `gbforge/engine/sim.py`'s. Under a second. Also runs the asset
contract checks.

**`make -C harness test`** — the ROM under emulation, ~1.2s.
`harness/gbctl` links libsameboy and speaks the line protocol
(`harness/PROTOCOL.md`); `harness/pygb` drives it. Read
[harness/README.md](harness/README.md) first. The essentials:

- **Symbols.** Building emits `cascadia.noi` next to the ROM — a
  symbol table mapping every non-static C variable to its address.
  `pygb` parses it per-ROM; never hardcode an address, and never
  resolve a dev-ROM name against the retail table (the mailbox shifts
  everything declared after it).
- **The debug mailbox** (`runtime/debug.h`, dev builds only). Write
  args, then the request byte; the game clears it when consumed.
  `enter_mode` jumps in from the title, `trigger_swap` performs a swap
  as if it were input, `redraw` repaints after you rewrite `board[][]`,
  and `debug_rng_force`/`debug_rng_seed` make the board deterministic.
- **Checkpoints** are recipes (`harness/checkpoints/recipes/`), not
  committed savestates; the cache is keyed by the ROM's SHA1.
- **Goldens** live in `harness/golden/` and are regenerated by
  `harness/scripts/update_golden.py` — *after looking at the frames*.
  A golden updated reflexively turns a regression suite into a
  recorder.

**Capture-first for visual bugs.** When fixing a rendering bug:
capture frames showing it, write a detector that FAILS on the current
ROM, *then* fix, then watch the detector flip. A detector that was
never seen to fail is not evidence — it may be testing a stand-in
property rather than the bug. Two mutations are known to be caught by
the current suite (a changed scoring constant; a revert that repaints
without restoring the model); if you add a test, know which mutation
it catches.

`scripts/editor-roundtrip.sh` is the fourth check and the slowest
(~12s, compiles Swift). It runs in `verify.sh` via the contract tests.

## Rules that keep this repo healthy

- **Never hand-edit machine-made files.** `examples/*/generated/` and
  the generated half of `examples/*/res/` are outputs. Change the spec
  (`cascadia.py`), the generators (`gbforge/codegen/`), or
  `scripts/gen_placeholder_res.py`, then regenerate.
- **Respect res ownership.** `tiles_data.c`, `palettes.c` and
  `spell_icons.c` belong to the sprite editor: `make res` seeds them
  once and will not overwrite them (`--force` to insist). A symbol the
  editor does not round-trip must not live in a file the editor
  rewrites — `tests/test_asset_contracts.py` enforces this, and it
  exists because the first real export produced a ROM that would not
  link.
- **Generated code is data, not logic.** Codegen emits `const` tables.
  If a change needs generated control flow, that's a design
  discussion, not a patch.
- **BANKED discipline in the runtime.** Files with `#pragma bank N`
  must declare every public function `BANKED` (in the header too).
  A non-BANKED function in a banked file compiles into a direct,
  un-switched call that works only while its bank happens to be
  mapped — the failure is a wild jump, found the hard way.
- **`NONBANKED` for interrupt-time code.** `runtime/bandpal.c` runs
  from an LYC ISR with arbitrary banks mapped; everything it touches
  lives in HOME.
- **Hardware constraints are real:** no malloc, no float, no division
  in per-frame paths (lookup tables instead), `uint8_t` for tile
  values, VRAM writes batched into blanking windows. Do the
  arithmetic *before* the blanking window, not inside it.
- **Don't trust SDCC silently.** It has miscompiled a variable shift
  in this codebase (`hud.c` uses a mask table because of it). If
  behaviour disagrees with the source, check the `.asm` in `obj/`.
- **No new dependencies** — Python stdlib, GBDK, and the host C and
  Swift toolchains. If a task seems to need one, stop and surface it.
- **No borrowed assets.** Everything visual ships from
  `gen_placeholder_res.py` or the editor. Nothing from commercial
  ROMs, other projects, or unlicensed libraries goes in this tree.
- **Measure, don't estimate.** Any count destined for the README
  (`wc -l`, file counts) is measured from the tree at commit time.

## Layout

```
gbforge/            the model, codegen, and pure-Python reference sim
  model/            dataclasses a spec instantiates (Game, Mode, ...)
  model/assets.py   parses the editor-owned res/ into a manifest
  codegen/          one emitter per concern -> const C tables
  engine/sim.py     reference board engine (mirrors runtime/engine.c)
runtime/            shared C runtime; hot paths hand-written
examples/cascadia/  spec + glue + generated output + ROM, all committed
harness/            gbctl (headless libsameboy) + pygb + scenarios
tests/              host-native transcript oracle + asset contracts
tools/sprite-editor/ SwiftUI tile + palette editor, owns res/*.c
scripts/            asset generation, bank checker, verify, gates
```
